# Сайт-афиша фото дней и скидок для фотографа

Рекламный сайт (и Telegram Mini App): анонсы фото дней и скидок в двух городах —
**Москва** и **Геленджик**. Клиент переключает город свайпом, выбирает анонс,
записывается строго на одну из заданных фотографом дат и оплачивает запись
(тестовый платёж). Первый экран — информация о фотографе и фоновый видеоролик
(по желанию). Один статический фронтенд (`index.html`) и serverless-бэкенд на
Vercel Functions (`api/*.js`) с хранением данных в Vercel Blob.

---

## Как это выглядит для клиента

- **Первый экран** — имя фотографа, пометка «сайт-афиша фото дней и скидок»,
  кнопка «Связаться» и фон: видео (если загружено) либо главное фото, либо заглушка.
- **Фото дни и скидки** — первым открывается город, который фотограф задал
  в админке (пока не задан — Москва). Переключение городов: чипсы
  «Москва / Геленджик» и горизонтальный свайп по списку анонсов. В каждом
  городе — свой список: название, описание в два столбца (слева форматированный
  текст: жирный, курсив, списки, ссылки, переносы строк; справа фото анонса,
  если оно добавлено — клик открывает его крупно), даты (только те, что задал
  фотограф), цена, зачёркнутая цена до скидки с процентом, размер предоплаты.
  Если фото к анонсу нет, описание занимает всю ширину, как раньше.
- **«Записаться»** открывает страницу записи: выбор даты исключительно из дат
  анонса, имя, контакт, время, комментарий, три подтверждения юридических
  документов. После отправки — тестовая оплата (предоплата или полная цена).
- **«Мои заказы»** — записи клиента со статусами; находятся по Telegram-аккаунту
  (видны с любого устройства) с тихим запасным списком устройства.
- **Примеры работ** — фото-стенка на каждой городской странице (без фильтров).

## Структура проекта

```
index.html      — всё клиентское приложение: афиша, запись, «Мои заказы», админ-панель
vercel.json     — маршруты и заголовки безопасности (CSP и др.)
package.json    — зависимость @vercel/blob и "type": "module" (обязательно для ESM-функций)
api/
  _blob.js      — работа с Vercel Blob (чтение/запись)
  _lib.js       — общая логика: токены, пароль, города, санитизация анонсов/фото/видео, Telegram-уведомления
  health.js     — GET  /api/health   — самопроверка настроек (наружу только ok; детали — с токеном фотографа)
  login.js      — POST /api/login    — вход фотографа по паролю
  state.js      — GET/POST /api/state — анонсы, документы, фото/видео; «Возвраты» — только админу
  orders.js     — GET  /api/orders   — все записи (только админ)
  order.js      — GET/POST /api/order — запись клиента: создание по анонсу, чтение, тестовая оплата, «мои записи» по подписанному Telegram
  upload.js     — POST /api/upload   — загрузка фото, видео и документов (только админ)
  file.js       — GET  /api/file     — раздача фото, видео и документов
```

Файлы и данные в Blob-хранилище: `meta/state.json` (анонсы + фото/видео + документы + возвраты),
`meta/orders.json` (записи), `photos/*.jpg`, `videos/*.mp4|webm`, `docs/*`.

## Деплой: GitHub → Vercel, пошагово

1. **Загрузите проект на GitHub** — все файлы из этой папки в корень репозитория.
   Никакой сборки нет: Vercel сам определит проект как «Other» (статика + функции).

2. **Vercel → Add New… → Project → Import** репозитория.
   Ничего не меняйте в Build settings — фреймворк «Other», команда сборки не нужна. Deploy.

3. **Подключите хранилище**: вкладка проекта **Storage → Create Database → Blob**.
   Доступ выбирайте **Private** (рекомендуется: файлы читаются только через наши функции).
   Подключите созданный стор к проекту (Storage → Projects → Connect to Project) —
   Vercel сам добавит нужные переменные (`BLOB_READ_WRITE_TOKEN` и/или OIDC).

4. **Задайте переменные окружения**: Settings → Environment Variables.

   | Переменная | Обязательна | Значение |
   |---|---|---|
   | `ADMIN_PASSWORD` | да | пароль входа в админку. Не короче 12 символов |
   | `ADMIN_SECRET` | нет | отдельный ключ для подписи токенов; если не задан, используется `ADMIN_PASSWORD`. Смена этого ключа разлогинивает все сессии |
   | `TELEGRAM_BOT_TOKEN` | да, для «Моих заказов» | токен бота (у @BotFather) — привязывает «Мои заказы» к Telegram-аккаунту (видны с любого устройства) и включает уведомления о записях |
   | `TELEGRAM_CHAT_ID` | нет | куда слать уведомления (ваш chat id; узнать можно у @userinfobot) |
   | `BLOB_ACCESS` | нет | задавать не нужно; только если создали **публичный** стор — тогда `public` |

   После добавления переменных сделайте **Redeploy** (Deployments → ⋯ → Redeploy).

5. **Проверьте**: откройте `https://ваш-домен/api/health` — должно быть
   `{"ok":true}` (наружу отдаётся только общий статус, подробные подсказки видит
   только вошедший фотограф — ссылка «Проверить настройки сервера» внизу админки).
   Уведомления Telegram проверяются по-настоящему: при нажатии этой ссылки бот
   пришлёт вам тестовое сообщение, а если пара «токен + chat id» не работает,
   в отчёте будет точная ошибка (например, «chat not found» — неверный chat id
   или у бота не нажат Start).
   Затем откройте `https://ваш-домен/admin`, войдите с `ADMIN_PASSWORD` и один раз
   нажмите «Сохранить» (вкладка «Анонсы», любое изменение) — это создаст
   `meta/state.json` с вашими данными.

6. **Подключите мини-приложение в Telegram**: у @BotFather → `/mybots` → ваш бот →
   **Bot Settings → Menu Button → Configure menu button** → URL `https://ваш-домен/`.
   Для веб-версии Telegram этого достаточно. Админка открывается любым из способов:
   обычным браузером по адресу `https://ваш-домен/admin`; из Telegram — ссылкой
   `https://t.me/ваш_бот?startapp=admin` (мини-приложение откроется сразу с экраном
   входа фотографа, удобно управлять сайтом прямо с телефона); либо адресом
   `https://ваш-домен/?admin` в любом браузере. Везде вводится `ADMIN_PASSWORD`.

7. **Локальная разработка** (по желанию): `npm i`, затем `vercel link`,
   `vercel env pull` (подтягивает переменные проекта) и `vercel dev` — сайт на
   `http://localhost:3000`. Открытие `index.html` двойным кликом работает как
   демо-режим без сервера (данные только в этом браузере, демо-анонсы для наглядности).

## Как пользоваться (для фотографа)

- **Анонсы** (вкладка «Анонсы»): создайте анонс, выберите город, напишите название
  и описание, задайте цену, при желании — «цену до скидки» (клиент увидит
  зачёркнутую цену и процент) и «предоплату сейчас» (если не указать, клиент
  оплачивает полную цену при записи). Добавьте даты фото дня — **клиент сможет
  записаться только на них**. Включите галочку «Показывать клиентам».
  Описание редактируется визуально: панель над полем делает выделенный текст
  жирным/курсивом/подчёркнутым/зачёркнутым, собирает маркированные и нумерованные
  списки, вставляет ссылки (https, mailto, tel). Enter — новая строка, вставка из
  Word и мессенджеров превращается в чистый текст с переносами; описание
  сохраняется автоматически при выходе из поля.
  Под описанием — **«Фото к описанию»**: выберите изображение, и на сайте оно
  встанет справа от текста описания (в два столбца; на узких экранах столбец
  с фото чуть уже). Фото сжимается до 1600 px и загружается сразу при выборе
  файла; превью показывается тут же, кнопка «Убрать» отсоединяет его от анонса.
  Новая загрузка заменяет текущее фото. Анонс можно сохранить и без фото —
  тогда описание занимает всю ширину.
- **Город первой страницы** (карточка вверху вкладки «Анонсы»): выберите, какой
  город открывается посетителям при заходе на сайт — например, Геленджик на время
  съёмок там. Выбор посетителя внутри сессии не перекрывается, свайп и чипсы работают
  как раньше.
- **Фото** (вкладка «Фото»): загрузите видео для первого экрана (MP4/WebM, до
  3,5 МБ, без звука, зациклится) или назначьте главное фото кнопкой ◇; загрузите
  фотографии и распределите их по городам — на сайте они показываются стенкой
  на странице соответствующего города, без фильтров.
- **Записи** (вкладка «Записи»): все записи клиентов, управление статусами — от
  «Ожидает оплаты» до «Завершён», подтверждение даты, консультации, заметки,
  видимые только вам.
- **Возвраты**: журнал запросов с суммой и основанием решения.
- **Документы**: редакции договора и политик; версии, подтверждённые клиентами
  в записях, фиксируются навсегда.

## Безопасность — что уже сделано

- **Вход фотографа**: пароль сравнивается в постоянном времени (защита от timing-атак),
  попытки входа ограничены (10 за 5 минут с одного IP + задержка ответа).
- **Токен сессии** — `срок_действия.HMAC-подпись`, проверяется на сервере в каждом
  защищённом запросе; подделать нельзя, срок жизни 30 дней. Смена `ADMIN_PASSWORD`
  или `ADMIN_SECRET` мгновенно инвалидно все токены.
- **Цены и даты назначает сервер**: клиент присылает только id анонса и выбранную
  дату; сумма, предоплата и versions юридических документов берутся из сохранённого
  анонса на сервере. Дата принимается **только если она есть в списке дат анонса** —
  записаться на произвольную дату или подменить цену через DevTools нельзя.
- **Анти-спам**: на создание записей и список «моих записей» действует лимит
  частоты с одного IP (щедрый — мобильные операторы делят один адрес на многих).
- **«Мои заказы» привязаны к Telegram-аккаунту клиента**: при каждом открытии
  мини-приложения Telegram подписывает initData, сервер проверяет подпись
  (данные старше суток не принимаются) и отдаёт записи только их владельцу —
  на любом устройстве, где клиент вошёл в свой Telegram. В обычном браузере
  (вне Telegram) работает тихий запасной список этого устройства. Для этого
  требуется задать `TELEGRAM_BOT_TOKEN`.
- **Заметка фотографа** (`note`) вырезается из ответов клиенту.
- **Загрузка файлов** — только фотограф; пути жёстко валидируются (только
  `photos/…jpg`, `videos/…mp4|webm` и `docs/…` с белым списком расширений),
  проверяются сигнатуры контейнеров (JPEG, PDF, MP4/MOV `ftyp`, WebM EBML),
  лимит 4 МБ (потолок Vercel — 4.5 МБ на тело запроса). Кросс-подмена папок
  отсекается (видео в `photos/` не пройдёт проверку типа).
- **Path traversal** в `/api/file` и `/api/upload` исключён шаблоном пути.
- **XSS**: все данные, попадающие в HTML, экранируются на клиенте (`esc()`),
  сервер приводит строки к ограниченной длине и сверяет id фото/видео, фото
  анонса (`ev.img` — только id вида «p<число>», не путь) и город
  с жёстким шаблоном; CSP в `vercel.json` ограничивает источники скриптов и стилей.
  Форматированное описание анонса проходит серверный фильтр `richText()`
  (`api/_lib.js`): наружу пропускается только простая разметка (жирный, курсив,
  подчёркивание, зачёркивание, списки, абзацы, переносы, ссылки), скрипты, стили,
  обработчики событий, атрибуты и незнакомые теги удаляются, ссылки живут только
  на `http(s):`, `mailto:` и `tel:`; фильтр применяется и при сохранении, и при
  чтении, поэтому записи старых версий сайта тоже очищаются.
- **Раздел «Возвраты»** и заметки отдаются только с токеном фотографа.
- **Устройство проекта не раскрывается посетителям**: экран входа не упоминает
  хостинг и переменные окружения; `/api/health` без токена отдаёт только
  `ok:true/false` без подсказок; сообщение о ненастроенном сервере нейтральное.

## Ограничения и особенности (важно знать)

- **Оплата — тестовая** (заглушка из ТЗ): никаких денег не списывается. Перед
  приёмом реальных платежей нужно подключить платёжного провайдера.
- **Видео фона**: из-за потолка Vercel 4.5 МБ на запрос ролик должен быть коротким
  (до 3,5 МБ) и без звука — это зацикленный фон, а не полноценный фильм. Для
  большого видео подойдёт ссылка на CDN (потребует доработки).
- **Смена дат/цен анонса** не влияет на уже созданные записи: в каждой записи
  зафиксирован снимок цены на момент создания.
- **Гонки записи**: Vercel Blob не имеет транзакций. Записи пишутся схемой
  «прочитал → изменил → записал → перечитал для проверки» (до 5 попыток). Для одного
  фотографа этого достаточно; одновременные записи в одну и ту же миллисекунду
  теоретически могут потребовать повтора у клиента.
- **Удалённые фото/видео** остаются в Blob как файлы (запись в афише удаляется).
  Раз в сезон можно почистить через Vercel Dashboard → Storage → Browse.
- **Rate-limit входа и записей** живёт в памяти инстанса функции: при почти
  одновременных запросах на разных инстансах лимит слегка мягче — это нормально.
- **Часовой пояс журнала записей** — Europe/Moscow.
- **Города зашиты в двух местах**: `CITIES` в `api/_lib.js` и в `index.html` —
  если решите добавить третий город, правьте синхронно (и добавьте ветку в
  переключателе на клиенте).
