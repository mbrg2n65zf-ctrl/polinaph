# Telegram Mini App для фотографа

Каталог услуг с ценами, приём заявок, галерея портфолио (главное фото и отбор лучших
снимков настраиваются в админ-панели), тестовая оплата первого взноса
и отдельная админ-панель фотографа. Один статический фронтенд (`index.html`) и
серверless-бэкенд на Vercel Functions (`api/*.js`) с хранением данных в Vercel Blob.

---

## Структура проекта

```
index.html      — всё клиентское приложение: витрина, «Мои заказы», админ-панель
vercel.json     — маршруты и заголовки безопасности (CSP и др.)
package.json    — зависимость @vercel/blob и "type": "module" (обязательно для ESM-функций)
api/
  _blob.js      — работа с Vercel Blob (чтение/запись)
  _lib.js       — общая логика: токены, пароль, санитизация данных, Telegram-уведомления
  health.js     — GET  /api/health   — самопроверка настроек (наружу только ok; детали — с токеном фотографа)
  login.js      — POST /api/login    — вход фотографа по паролю
  state.js      — GET/POST /api/state — каталог, документы, фото; «Возвраты» — только админу
  orders.js     — GET  /api/orders   — все заявки (только админ)
  order.js      — GET/POST /api/order — заявка клиента: создание, чтение, тестовая оплата, «мои заявки» по подписанному Telegram
  upload.js     — POST /api/upload   — загрузка фото и документов (только админ)
  file.js       — GET  /api/file     — раздача фото и документов
```

Файлы и данные в Blob-хранилище: `meta/state.json` (каталог + фото + документы + возвраты),
`meta/orders.json` (заявки), `photos/*.jpg`, `docs/*`.

## Деплой: GitHub → Vercel, пошагово

1. **Загрузите проект на GitHub** — все файлы из этой папки в корень репозитория.
   Никакой сборки нет: Vercel сам определит проект как «Other» (статика + функции).

2. **Vercel → Add New… → Project → Import** репозитория.
   Ничего не меняйте в Build settings — фреймворк «Other», команда сборки не нужна. Deploy.

3. **Подключите хранилище**: вкладка проекта **Storage → Create Database → Blob**.
   Доступ выбирайте **Private** (рекомендуется: файлы читаются только через наши функции).
   Подключите созданный стор к проекту (Storage → Projects → Connect to Project) —
   Vercel сам добавит нужные переменные (`BLOB_READ_WRITE_TOKEN` и/или OIDC).

4. **Задайте переменные окружения**: Settings → Environment Variables.

   | Переменная | Обязательна | Значение |
   |---|---|---|
   | `ADMIN_PASSWORD` | да | пароль входа в админку. Не короче 12 символов |
   | `ADMIN_SECRET` | нет | отдельный ключ для подписи токенов; если не задан, используется `ADMIN_PASSWORD`. Смена этого ключа разлогинивает все сессии |
   | `TELEGRAM_BOT_TOKEN` | да, для «Моих заказов» | токен бота (у @BotFather) — привязывает «Мои заказы» к Telegram-аккаунту (видны с любого устройства) и включает уведомления о заявках |
   | `TELEGRAM_CHAT_ID` | нет | куда слать уведомления (ваш chat id; узнать можно у @userinfobot) |
   | `BLOB_ACCESS` | нет | задавать не нужно; только если создали **публичный** стор — тогда `public` |

   После добавления переменных сделайте **Redeploy** (Deployments → ⋯ → Redeploy).

5. **Проверьте**: откройте `https://ваш-домен/api/health` — должно быть
   `{"ok":true}` (наружу отдаётся только общий статус, подробные подсказки видит
   только вошедший фотограф — ссылка «Проверить настройки сервера» внизу админки).
   Уведомления Telegram проверяются по-настоящему: при нажатии этой ссылки бот
   пришлёт вам тестовое сообщение, а если пара «токен + chat id» не работает,
   в отчёте будет точная ошибка (например, «chat not found» — неверный chat id
   или у бота не нажат Start).
   Затем откройте `https://ваш-домен/admin`, войдите с `ADMIN_PASSWORD` и один раз
   нажмите «Сохранить» (вкладка «Каталог», любое изменение) — это создаст
   `meta/state.json` с вашим каталогом.

6. **Подключите мини-приложение в Telegram**: у @BotFather → `/mybots` → ваш бот →
   **Bot Settings → Menu Button → Configure menu button** → URL `https://ваш-домен/`.
   Для веб-версии Telegram этого достаточно. Админка открывается любым из способов:
   обычным браузером по адресу `https://ваш-домен/admin`; из Telegram — ссылкой
   `https://t.me/ваш_бот?startapp=admin` (мини-приложение откроется сразу с экраном
   входа фотографа, удобно управлять сайтом прямо с телефона); либо адресом
   `https://ваш-домен/?admin` в любом браузере. Везде вводится `ADMIN_PASSWORD`.

7. **Локальная разработка** (по желанию): `npm i`, затем `vercel link`,
   `vercel env pull` (подтягивает переменные проекта) и `vercel dev` — сайт на
   `http://localhost:3000`. Открытие `index.html` двойным кликом работает как
   демо-режим без сервера (данные только в этом браузере).

## Безопасность — что уже сделано

- **Вход фотографа**: пароль сравнивается в постоянном времени (защита от timing-атак),
  попытки входа ограничены (10 за 5 минут с одного IP + задержка ответа).
- **Токен сессии** — `срок_действия.HMAC-подпись`, проверяется на сервере в каждом
  защищённом запросе; подделать нельзя, срок жизни 30 дней. Смена `ADMIN_PASSWORD`
  или `ADMIN_SECRET` мгновенно инвалидно все токены.
- **Цены считает сервер**: клиент присылает только id тарифа и допуслуг; итоговая
  сумма, первый платёж и версии юридических документов фиксируются на сервере —
  подменить стоимость через DevTools нельзя.
- **«Мои заказы» привязаны к Telegram-аккаунту клиента**: при каждом открытии
  мини-приложения Telegram подписывает initData, сервер проверяет подпись
  (данные старше суток не принимаются) и отдаёт заявки только их владельцу —
  на любом устройстве, где клиент вошёл в свой Telegram. В обычном браузере
  (вне Telegram) работает тихий запасной список этого устройства. Для этого
  требуется задать `TELEGRAM_BOT_TOKEN`.
- **Заметка фотографа** (`note`) вырезается из ответов клиенту.
- **Загрузка файлов** — только фотограф; пути жёстко валидируются (только
  `photos/…jpg` и `docs/…` с белым списком расширений), проверяются магические
  байты JPEG/PDF, лимит 4 МБ (потолок Vercel — 4.5 МБ на тело запроса).
- **Path traversal** в `/api/file` и `/api/upload` исключён шаблоном пути.
- **XSS**: все данные, попадающие в HTML, экранируются на клиенте (`esc()`),
  дополнительно сервер приводит строки к ограниченной длине и сверяет id фото/альбомов
  с жёстким шаблоном; CSP в `vercel.json` ограничивает источники скриптов и стилей.
- **Раздел «Возвраты»** и заметки отдаются только с токеном фотографа.
- **Устройство проекта не раскрывается посетителям**: экран входа не упоминает
  хостинг и переменные окружения; `/api/health` без токена отдаёт только
  `ok:true/false` без подсказок; сообщение о ненастроенном сервере нейтральное.

## Ограничения и особенности (важно знать)

- **Оплата — тестовая** (заглушка из ТЗ): никаких денег не списывается. Перед
  приёмом реальных платежей нужно подключить платёжного провайдера.
- **Гонки записи**: Vercel Blob не имеет транзакций. Заявки пишутся схемой
  «прочитал → изменил → записал → перечитал для проверки» (до 5 попыток). Для одного
  фотографа этого достаточно; одновременные заявки в одну и ту же миллисекунду
  теоретически могут потребовать повтора у клиента.
- **Удалённые фото** остаются в Blob как файлы (запись в каталоге удаляется).
  Раз в сезон можно почистить через Vercel Dashboard → Storage → Browse.
- **Rate-limit входа** живёт в памяти инстанса функции: при почти одновременных
  запросах на разных инстансах лимит слегка мягче — это нормально.
- **Часовой пояс записей в журнале заявок** — Europe/Moscow.
- Файл `api/_lib.js` содержит резервный каталог тарифов (S0/A0) — если поменяете
  тарифы в `index.html` по умолчанию, синхронно поменяйте их там же. После первого
  сохранения каталога из админки сервер всегда использует сохранённую версию.
